台灣用語調教手冊 v2.4
適用：商管專欄／財經分析／研究報告／政策簡報稿／新聞整理
主旨：把 AI 產出的「陸式用語、翻譯腔、口播感、黑話官腔」改成台灣常見書面中文；同時重整段落以符合台灣常見文章結構。

0. 快速使用方式（給你每次貼文的固定做法）

你每次貼上文章時，請在最上方用三行設定（可省略，省略則採預設）：

* 文章類型：商管專欄／財經分析／研究報告／政策簡報稿／新聞整理（預設：商管專欄）
* 修整強度：快修／標準／深修（預設：標準）
* 目標讀者：一般讀者／企業主管／學術讀者（預設：企業主管）

技能預設輸出：
A. 修訂後全文（繁體、台灣常用語）
B. 實際替換清單（只列有改到的）
C. 結構與語氣調整摘要（5–10 點）

如你輸入「只要乾淨全文」，只輸出 A（不附 B/C）。

0.1 最高優先快篩（先掃這些句型｜S2–S3）

本手冊把下列句型視為「高頻口播模板」。只要出現，先改成可核對的書面句，再進入其他用詞與段落調整。

* 口號式並列（例：「把A…、把B…、把C…」）：改為「目標/順序＋可稽核名詞」，必要時補上門檻與責任角色。
  * 句型模板：導入的優先順序很清楚：A 要能…；B 要能…；C 要能…。
* 二分斷言模板（例：「不是A，而是B」「價值不在A，而在B」「要的是A，而不是B」）：改為「主次/條件/邊界」的層次敘述，避免把複雜議題硬切成兩邊。
  * 句型模板：A 常被拿來討論，但若要擴大導入，先決條件其實是 B（因為…）。
* 目的句懸空（例：「才能…」「以便…」）：檢查前文是否交代機制與條件；若沒有，先補「因此/所以/若要…需先…」並寫出門檻。
* 「收斂成一句話／三句話收斂」：改為「可概括為三項」「可整理為三點」等中性說法，避免「壓/收斂」這類黑話動詞。
* 流程控點一口氣堆疊（括號＋頓號＋符號，例如「入口…（…）、中間…（…）、輸出前…、最後…」）：拆成 3–5 句或改成冒號＋分號，確保層級可讀。
* 時程口播（例：「用一個月跑出…」）：改為「四週內完成…並建立…」，避免「跑出」動作詞。
* 收尾帶讀或情緒提示（例：「最後提醒一點現實…」）：改為「限制／前提／治理要求」段落，寫清楚何時成立、何時不成立。

快篩關鍵詞：把、不是…而是、價值不在、要的是、才能、收斂、壓成一句話、跑出、塞回、入口/中間/輸出前/最後。


1. Skill Contract

1.1 輸入（Input）

* text：原文（可含標題、小標、引用、數字、英文縮寫）
* （新增）若 text 含 HTML：只改可見文字，不改標籤、屬性、<script>/<style> 內容與程式碼字串；避免因改字破壞版面或互動。
* config（可選）：

  * doc\_type：商管專欄｜財經分析｜研究報告｜政策簡報稿｜新聞整理
  * intensity：快修｜標準｜深修
  * audience：一般讀者｜企業主管｜學術讀者
  * tai\_variant：台｜臺（預設：台；若原文全程用「臺灣」，則自動跟隨）
  * output\_mode：full｜clean\_only（預設：full）
  * glossary（可選）：使用者提供的術語表（優先遵守）

1.2 產出（Output）

* revised\_text：修訂後全文（必出）
* replacements：替換清單（output\_mode=full 才出）
* edit\_summary：段落/語氣/句式調整摘要（output\_mode=full 才出）
* lint\_report（可選）：若 intensity=深修，額外給出 tag 統計與高風險句型清單（方便你維護規範）

1.3 不能做（Non-goals）

* 不查證、不新增未提供的數據、案例、引述或指控（除非使用者要求另做研究）
* 不擅自改動專有名詞（公司名、人名、法規、機構、產品、地名、統計口徑）
* 不把台式改寫變成文青抒情或口號文（偏《天下》：清楚、直接、少灑狗血）

2. 核心原則（Hard Principles｜任何強度都必守）

P0 先掃高頻口播模板：遇到「把…把…」「不是…而是…」「價值不在…而在…」「要的是…而不是…」「才能…」「收斂/壓成一句話」與「流程控點同句堆疊」等句型，優先改寫成主次清楚、可核對、可追溯的書面句（見 0.1 與 7.14）。

P1 意義優先：保留原文立場、論點方向、關鍵定義，不把推測改寫成事實。
P2 名詞保護：專有名詞原則不改；必要時可用「中文（English）」第一次標註一次，後續只用中文。
P3 台灣常用語優先：遇到兩岸差異詞，優先採教育部兩岸常用詞語對照表的台灣側用法。([國語辭典簡編本](https://dict.concised.moe.edu.tw/appendix.jsp?ID=54&la=0&powerMode=0))
P4 降低口播帶讀：移除或改寫「你看／你要明白／你注意」等命令式推進句。
P5 降低二分斷言：把「不是A是B、本質就是、一定會」改成條件句/可能性/邊界敘述。
P6 段落清楚：一句一意、段落功能點”閱讀習慣。

3. Lint 分類與嚴重度（讓規則可執行、可回溯）

3.1 Lint Tags（12 類）
T01 兩岸差異詞（例：質量、信息、視頻、軟件、賬號、報道）
T02 簡體/字形問題（账/賬、数、这…）
T03 商務/供應鏈陸式術語（回款、甲方、渠道、對標、賽道、落地…）
T04 體制官腔（穩增長、口徑、指標往前推、招商…）
T05 互聯網黑話（賦能、抓手、閉環、顆粒度、路徑、做大做強、壓成一句話…）
T06 翻譯腔模板（很＋抽象評語、英文句構直譯、名詞堆疊）([編譯論叢](https://ctr.naer.edu.tw/v13.2/ctr130203.pdf))
T07 句尾半截/單字收尾（在長、在降、在卷、在改…）
T08 口播帶讀/模板句（你看、你要明白、不是…而是…、價值不在…而在…、要的是…而不是…、把…把…）
T09 情緒放大器（刺骨、塌陷、崩塌、最致命、更狠…）
T10 現象堆疊→宏大結論（片段堆疊後直接上綱）
T11 軍事/戰爭隱喻、宏大敘事（戰略高地、鉗形攻勢、降維打擊、百年未有之大變局…）([MURAL](https://mural.maynoothuniversity.ie/id/eprint/20178/))
T12 標點/括號/全半形濫用（過量引號、三層括號、中文英數全形半形混亂）([語文成果入口網](https://language.moe.gov.tw/001/upload/files/site_content/m0001/hau/Revised_Handbook_of_Punctuation.pdf))

3.2 嚴重度（Severity）
S3（必改）：一看就“非台灣書面語”，或造成語意懸空/不通順（T02、T07、明顯支語 T01/T03、戰爭口號 T11、錯誤全半形 T12）
S2（高優先）：讀者會感到“很陸/很口播/很像直譯”（T04、T05、T06、T08、T09）
S1（建議）：可讀性可再提升（冗語、名詞堆疊、過度倒裝、括號略多）
S0（保留）：台灣也常用或屬通用詞（見第 10 節“不要誤改”）

4. 多輪處理流程（Pass-based Pipeline）

本技能採「先掃描、再改寫、後重排、再校對」四段式。

Pass 0：正規化（Normalization）

* 簡轉繁（若原文含簡體）
* 統一台/臺、裡/裏、後/后 等用字（依原文/設定）
* 全半形：中文與中文標點全形；英數與其標點半形（行政院文書處理手冊）([行政院](https://www.ey.gov.tw/File/955BDB8CECCB1C44?A=C))

* （新增）HTML 安全模式（若輸入含 HTML）：
  * 先把 <script>、<style>、<code>、pre、以及所有標籤屬性值視為「保護區」，不做任何字詞替換。
  * 只處理可見文字節點（常見：h1/h2/h3/p/li/span/div 的純文字），並保留原本換行與空白節奏。
  * 若文字以 JSON/JS 字串形式嵌在 script 內（例如 slides 資料陣列），一律先抽出成純文字再套用本手冊，最後再貼回（避免破壞跳脫字元）。

Pass 1：詞彙層（Lexicon）

* 先處理 S3：兩岸差異詞、簡體字形、明顯黑話詞
* 再處理 S2：官腔、互聯網黑話、情緒放大器
* 產出 replacements（原詞→建議詞→原因 tag）

Pass 2：句式層（Syntax）

* 修正句尾半截、在＋單音節、怪異倒裝、被字句濫用
* 把命令式帶讀改成「可觀察到／值得留意的是／在…情境下」
* 把二分斷言改成保留邊界的推論句式
* 先做「高頻口播模板快篩」（把…把…、不是…而是…、價值不在…而在…、要的是…而不是…、才能…、收斂/壓成一句話、流程控點同句堆疊），再進入其他句式調整（見 0.1 與 7.14）

Pass 3：段落層（Paragraphing）

* 依 doc\_type 套用段落骨架（第 9 節）
* 目標是：觀察→機制→推論→影響→限制→指標
* 每段 2–4 句、一句一意；長句拆成 2–3 句（避免翻譯腔調）

Pass 4：全文層（Structure）

* 加小標或段落功能句（若 doc\_type=研究報告/政策簡報稿/新聞整理）
* 把「故事堆疊」移到“體感觀察/例子”段，避免直接上綱
* 加上限制/替代解釋（深修必做；標準視需要）

Pass 5：一致性校對（Consistency Gate）

* 名詞一致（供應鏈/產業鏈、收款/回收、帳期/回收期…）
* 數字單位一致（%、％、億元/億、幣別）
* 文體一致（避免一段學術、一段網路口語）

5. 段落重排規則（台灣常見文章寫法要求）

5.1 共通段落規格（所有 doc\_type 適用）

* 第一段先交代：本文要回答什麼、最重要結論/觀察是什麼（先說重點）
* 每段 2–4 句；每句只承載一個主要判斷或一個主要事實
* 先寫主幹（主詞–動詞–受詞/補語），再補原因/條件/例子（降低翻譯腔）([編譯論叢](https://ctr.naer.edu.tw/v13.2/ctr130203.pdf))
* 少口號、多可核對：結尾避免“末日式口號”，改成「條件句＋可觀察指標＋限制」

5.2 “先說重點”在台灣常見的兩個版本
(1) 倒金字塔（新聞/公告/整理稿）
教育部新聞寫作教材建議以「倒寶塔」方式，依重要性由高到低陳述重點。([教育局網站](https://ws.moe.edu.tw/001/Upload/1/relfile/7848/41485/26b9c80a-69c9-49b8-b713-ab7971924a22.pdf))

(2) 金字塔原則（商管/分析/簡報）
nochinese.md 已把 Minto Pyramid 寫成：核心結論→3–4 支撐點→佐證→限制。

5.3 段落功能標籤（深修時必用）
把每段先在腦中標記功能（不必輸出標籤，但要依此重排）：

* 背景（範圍/情境）
* 觀察（發生什麼）
* 機制（為什麼）
* 影響（對誰、何時、透過什麼傳導）
* 風險/限制（哪些不確定、替代解釋）
* 指標（接下來看什麼）

6. 用詞替換表（合併版｜按優先級排列）

說明：左欄出現時，優先考慮右欄；但若屬專有名詞/制度名/直接引述，保留並在需要時補一行背景。

6.1 S3 必改：兩岸差異/高度辨識支語（教育部對照可查者優先）([國語辭典簡編本](https://dict.concised.moe.edu.tw/appendix.jsp?ID=54&la=0&powerMode=0))

* 質量（指 quality）→ 品質
* 信息 → 資訊
* 視頻 → 影片（或：影音內容；正式文可用「影片」）
* 軟件/硬件 → 軟體/硬體
* 屏幕 → 螢幕
* 賬號/賬戶/賬期/賬款 → 帳號/帳戶/帳期/帳款
* 報道 → 報導
* 端口 → 連接埠（資訊領域）
* 程序（指 program）→ 程式（若指 procedure 才是「程序」；此條要靠語境判斷）

6.2 S3 必改：商管陸式高頻詞（附件共同高頻）

* 回款/回款率 → 收款、款項回收／回收率／收款比例／收款進度
* 應收賬款 → 應收帳款
* 甲方 → 客戶／業主／發包單位／採購方（依語境）
* 渠道 → 通路／管道
* 對標 → 對照／比對／參考同業／以…為標竿（視語境）
* 賽道 → 市場領域／競爭場域／產業方向（避免硬造新詞）
* 落地（指實施）→ 上路／推動執行／導入／實作（“落地窗/出生/落到地面”才保留）
* 截止（指 until）→ 截至（時間/期限用法）
* 通過（指 via）→ 透過／藉由（通過=通行/通過審查時可保留）

6.3 S2 高優先：互聯網黑話（能換就換）

* 賦能 → 授權／增能／提升能力（優先改成具體動詞：提供資源、提升效率、改善流程）
* 抓手 → 著力點／工具／做法／關鍵作法
* 閉環 → 流程閉合／完整循環／形成回饋機制／前後衔接的流程
* 顆粒度 → 細緻程／步驟（可保留“路徑依賴”這類學術用法）
* 復盤 → 回顧／檢討／事後回顧
* 優化 → 改善／調整／最佳化（視語境；台灣也會說優化，但正式文建議改具體）
  * （補充）若 doc_type=政策簡報稿 或文字用於對外簡報/制度文件：建議把「優化」改成「改善/調整/最佳化」之一，避免被讀成口號詞。
* 做大做強 → 擴大規模／提升競爭力（避免口號）
* 壓成一句話 → 總結成一句話 

6.4 S2 高優先：情緒放大器（降噪）

* 最致命、更狠、刺骨、發涼、扎心、崩塌、坍塌 → 關鍵在於／更需要留意的是／壓力更直接／風險更高／顯著下滑／劇烈修正
  （原意如果是“嚴重”，就用“嚴峻/嚴重/不利”，但要補具體內容）

6.5 特別修正：禁止用「很硬」假裝台式

* 現實很硬、數字很硬 → 條件不樂觀／數字不漂亮／資源吃緊／壓力很直接／代價很高／現實限制很明確
  （這條是我在整合時因你的反饋新增的“誤修防呆”規則。）

6.6 S2–S3 高優先：AI 教學/顧問話術常見詞（容易有「模型味」）

說明：這些詞不一定「用錯」，但在台灣的商管專欄、研究報告、政策簡報或制度文件中，常被讀成口語黑話、直譯腔或簡報口播稿。對外或正式文本，建議改成「可核對、可執行」的名詞與動詞（說清楚對象、責任、機制）。

* 責任人 → 負責人／承辦人（依語境）
* 責任鏈 → 責任分工／權責關係／責任歸屬（依語境）
* 拍板（作動詞）→ 決策／定案／由主管決策（依語境）
* 回退機制 → 回溯與退回機制（技術/系統語境也可用「回滾與退回機制」）
* 人審 → 人工審查
* 人審後送出 → 經人工審查後送出／由記錄者審查後送出（若是會議紀錄/報告流程）
* 留痕 → 留下紀錄／留存紀錄
* 脈搏調查 → 快速調查／短問卷／定期小調查（避免直翻 pulse）
* 坑（比喻）→ 錯誤／陷阱／盲點（依語境）
* 解法 → 解方／作法／解決方式（依文體）
* 低風險高頻 → 低風險、高頻率／低風險且頻率高
* 比較能控 → 較為可控／較易控管
* 出域 → 離開公司／離開既有範圍（若指組織邊界或適用範圍）
* 吃人才 → 需要人才／高度依賴人才／人才需求高
* 技能卡 → 技能包（或：技能清單／技能說明卡；依教材版型）
* 診斷卡 → 診斷表（或：檢核表／診斷清單；依用途）
* 主管版三問 → 給主管參考的三個提問（或：主管可用的三個問題）

7. 句式規則庫（把“陸式口播/翻譯腔”改成台灣分析文）

7.1 禁止句尾半截（S3）

* ❌ 需求正在長／成本在高／價格在降／大家在卷
* ✅ 需求在增加/成長／成本偏高或持續上升／價格下滑／競爭加劇或出現削價競爭

7.2 命令式帶讀→觀察式（S2）

* ❌ 你要明白…／你注意…／你看…
* ✅ 值得留意的是…／可觀察到…／在…情境下，較可能出現…

7.3 二分法斷言→保留邊界（S2）

* ❌ 這不是週期問題，是系統問題
* ✅ 這可能不只是景氣循環，也反映資金/付款機制的結構性壓力（仍需檢驗是否集中於特定區域/制度）

7.4 翻譯腔“很＋抽象評語”→具體描述（S2）([編譯論叢](https://ctr.naer.edu.tw/v13.2/ctr130203.pdf))

* ❌ 很殘酷／很骨感／很直白
* ✅ 把代價具體化：對誰不利？代價是什麼？限制在哪？
  例：不是“很殘酷”，而是“若現金流週轉不及，短期可能影響交付與用工；但衝擊程度取決於帳期、客戶結構與備援資金”。

7.5 少倒裝、少名詞堆疊（S1–S2）

* 把「就…而言、在…層面上、基於…」大量堆疊改成順敘句
* 把「進行調整／予以推進」改成直接動詞「調整／推動」



7.6 被字與「用起來」的口語感：改成台灣常見的書面句（S2）

* 問題型：用「被」把句子拉長，或用「用起來」當結果描述，讀起來像翻譯腔或口播稿。
* 原則：優先用主動句；「用起來」改成「派得上用場／用得上／落地／真正用得到」。

  * ❌ 決定了策略能不能被用起來  
    ✅ 決定策略能不能落地／能不能派上用場／能不能真正用得到
  * ❌ 這套方法能不能被用起來，要看…  
    ✅ 這套方法能不能落地，要看…／這套方法能不能用得上，要看…

7.7 「卡」可以用，但要落在具體位置；避免「當然會卡／另一種卡」這類口語捷徑（S1–S2）

* 問題型：只說「卡」但不說卡在哪裡，會像聊天語氣；「當然會卡」「另一種卡」更像口頭反射句。
* 原則：用「卡住／卡關／推不動／不順」並補上卡點（注意力、權責、流程、資源、資訊）。

  * ❌ 你用同一套「策略的語言」硬套，當然會卡。  
    ✅ 你用同一套「策略的語言」硬是套上去，就很容易卡住。  
    ✅ 你用同一套說法硬套到不同情境，常常會卡在「怎麼做、誰負責」這一段。
  * ❌ 小企業如果這樣想，很容易陷入另一種卡。  
    ✅ 小企業如果這樣想，往往又會卡在另一個地方。  
    ✅ 小企業如果這樣想，很快就會卡關：想得到方向，卻做不成具體承諾。

7.8 抽象比較別用「薄／厚」問法：改成「吃緊／餘裕／能撐多久」（S2）

* 問題型：「有多薄」「哪一個最薄」是直翻式比喻，台灣書面分析較少這樣問。
* 原則：現金流、交付、人力等「緩衝」概念，改用「吃緊／餘裕／能撐多久／還剩多少空間」。

  * ❌ 現金流緩衝到底有多薄？  
    ✅ 現金流的餘裕還剩多少？  
    ✅ 帳上現金大概能撐幾週／幾個月？（視情境）
  * ❌ 這週最可能讓公司出事的是什麼？現金流、交付、留存、人才，哪一個最薄？  
    ✅ 這週最可能爆掉的是哪一塊？現金流、交付、留存、人才，哪一塊最吃緊／最沒緩衝？  
    ✅ 這週最需要先守住的是哪一關？現金流、交付、留存、人才，哪一關最危險？

7.9 指標描述避免「有沒有動」：改成「有沒有變／有沒有改善」（S1）

* ❌ 一週後只檢查兩件事：指標有沒有動？機制有沒有累積？  
  ✅ 一週後只檢查兩件事：指標有沒有改善／數字有沒有變？機制有沒有累積？  
  ✅ 一週後只看兩件事：趨勢有沒有往對的方向走？累積的機制有沒有留下來？

7.10 翻譯腔的「更可用／逼你回到現實」：改成台灣常用的操作語彙（S2）

* ❌ 更可用的方式，是把優勢拆成「防禦機制」。  
  ✅ 比較好用的做法，是把優勢拆開來看，拆成一套「防禦機制」。  
  ✅ 更實際的做法，是把「優勢」拆成可累積的防禦機制。
* ❌ 即使只是粗估，也會逼你回到現實。  
  ✅ 就算只是先粗略估一下，也會迫使你回到現場把帳算清楚。  
  ✅ 哪怕只是大概抓個數字，也會讓你不得不面對「值不值得做」這件事。

7.11 概念句避免硬翻：用台灣常見的定義句寫法（S2）

* ❌ 哪些底線必須守？  
  ✅ 哪些底線不能退／不能破？  
  ✅ 哪些原則是底線，不能因為協作就放掉？
* ❌ 解耦不是理念，而是在治理失敗時的風險控制。  
  ✅ 解耦不是什麼理念派主張，而是治理失靈時用來止血的風險控管手段。  
  ✅ 解耦不是為了好看，而是當治理機制撐不住時，先把傷害範圍控住。



7.12 AI 教學/顧問口播句：先抽象化情境，再改成台灣書面句

說明：這類句子常出現在工作坊、內訓或顧問簡報的口播稿。若要改成台灣常見的書面分析文（專欄/報告/政策簡報/制度文件），建議做兩件事：第一，把比喻詞換成可核對的名詞；第二，把「情緒推進」改成「動作＋責任＋機制＋條件」。

（A）情境：用「坑／踩到／地基」推進 → 改成「錯誤前提／問題類型／流程是否合理」

* ❌ 先把你帶進坑  
  ✅ 先讓你踩在錯誤前提上，後續只會越走越偏／讓你愈錯愈離譜
* ❌ 坑  
  ✅ 錯誤／陷阱／盲點（依語境）
* ❌ 流程地基對不對？  
  ✅ 流程對不對？／流程設計是否合理？
* ❌ 互動題：你現在踩到的是哪一種「錯位」？  
  ✅ 你現在遇到的是哪一種「錯位」？
* ❌ 在錯的地基上補 AI，只會把混亂放大。  
  ✅ 使用 AI 拯救不良流程，只是放大混亂。／流程若先天設計不良，再加 AI 只會把混亂放大。

（B）情境：試辦/試行說法含糊（「一起定」）→ 改成「每個試辦都要包括哪些要素」

* ❌ 每個試辦都要一起定：責任人、回退機制、留痕、閉環。  
  ✅ 每個試辦都要包括：負責人、回溯與退回機制、留下紀錄，以及流程閉合（或形成回饋機制）。

（C）情境：權責與決策用黑話（責任鏈、拍板、高風險拍板）→ 改成「責任歸屬/主管決策/定案」

* ❌ 責任鏈要先設計好。  
  ✅ 責任歸屬得由主管拍板定案。
* ❌ 高風險拍板：要不要上線？  
  ✅ 高風險事項由主管決策：是否上線？
* ❌ 這件事沒有責任人，最後一定會失控。  
  ✅ 這件事若沒有明確負責人（或承辦人），最後很容易失控。

（D）情境：審查與送出流程寫成直譯腔（人審、人審後送出）→ 改成「人工審查/由誰審查後送出」

* ❌ 會議紀錄先讓 AI 生成，人審後送出。  
  ✅ 會議紀錄先由 AI 生成，再由記錄者審查後送出。
* ❌ 報告人審後送出。  
  ✅ 報告經人工審查後送出。

（E）情境：比較句太硬、缺乏邊界（可控但昂貴、低風險高頻、比較能控）→ 補逗號與「可能」

* ❌ 人工審查比較可控但更昂貴。  
  ✅ 人工審查比較可控，但可能會更昂貴。
* ❌ 這類需求多屬低風險高頻。  
  ✅ 這類需求多屬低風險、高頻率。
* ❌ 這個方案比較能控。  
  ✅ 這個方案較為可控管。
* ❌ 目前的解法是先把門檻拉高。  
  ✅ 目前的解方（或作法）是先把門檻拉高。

（F）情境：教材/課程包裝詞太像簡報黑話（技能卡、診斷卡、主管版三問、能回去直接用）→ 改成台灣教材常見命名

* ❌ 這堂課會給你三張技能卡，回去直接用。  
  ✅ 這堂課會提供一份技能包，你可以帶回去，直接可用。
* ❌ 這份表能回去直接用。  
  ✅ 這份表能帶回去，直接可用。
* ❌ 我們先發診斷卡，再做主管版三問。  
  ✅ 我們先填一份診斷表，再提供給主管參考的三個提問。

（G）情境：英語直譯或不自然動詞（脈搏調查、出域、吃人才、先用一個常見情境）→ 改成台灣常見說法

* ❌ 下週我們做一次脈搏調查。  
  ✅ 下週我們做一次快速調查（或短問卷）。
* ❌ 這個流程一旦出域，就很難控。  
  ✅ 這個流程一旦離開公司（或超出適用範圍），就較難控管。
* ❌ 這類產品很吃人才。  
  ✅ 這類產品很需要人才／對人才的依賴度高。
* ❌ 先用一個常見情境：大家都想先上 AI，再說流程。  
  ✅ 一個常見情境是：大家都想先上 AI，再討論流程。

7.13 避免「AI 中文式語感」：句型補全與節奏校正（S2–S3）

說明：以下規則專門處理「看起來像中文、但讀起來不像台灣人寫作/說話」的句型問題；重點是把句子補回完整的主詞—動詞—受詞/補語，並把邏輯關係寫明。

（A）形容詞片語並列→補動詞/補語/連接詞（S3）
* ❌ 他很順、很像對。  
  ✅ 他答得很順暢，答案也像是對的，但結果卻錯得離譜。  
* 原則：避免「很X、很Y」直接並列；至少補上動詞（答得/看起來/呈現出）與轉折（但/然而/卻）。

（B）「像」後面要補齊（S3）
* ❌ 很像對／像對。  
  ✅ 像是對的／看起來像是正確的。  

（C）避免英文式平行結構（連續「要」）（S2）
* ❌ 每一段話要能回溯、要能驗收、出了問題要能改版。  
  ✅ 由 AI 生成的內容都要能回溯出處，並且能重複檢驗是否正確；如果出了問題，也要知道如何修正與改版，並留下改版紀錄。  
* 原則：同一句不要連續 3 次以上「要」；改用「都要…並且…；如果…也要…」把條件與後續動作講完整。

（D）少用隱喻動詞/口號句，改成可執行動作（S2）
* ❌ 把它關進流程裡／抓到一件事。  
  ✅ 接下來要用流程把生成結果管起來／我希望你們在一小時內理解一件事。  
* 原則：避免把英文隱喻直翻成中文（關進/抓到）；用「管理、控管、納入流程、回溯、檢驗、修正、記錄」等可執行動詞。

（E）避免短句斷裂：口號＋補充→中文複句（S2）
* ❌ 我只想讓你們抓到一件事。它不是偶爾答錯。它是錯得很安靜。  
  ✅ 我希望你們在一小時內理解：風險不在偶爾答錯，而在於它看起來合理，卻可能在關鍵細節上出錯。  

（F）30 秒句型自檢（S2）
* 每句至少能圈出：主詞＋核心動詞＋受詞/補語；缺一就重寫。  
* 關係詞要寫出來：因果用「因此/所以」，轉折用「但/然而/卻」，條件用「如果/在…情境下」。

7.14.1 快速掃描規則（字面匹配即可先抓）

* 同一句同時出現「不是」與「而是」（含「從來不是」）→ 先改為主次敘述或條件句。
* 出現「價值不在」「要的是」「而不是」→ 先改為「優先順序/評估準則」的寫法。
* 同一句「把」出現 3 次以上 → 多半是口號式並列，先改為「順序＋名詞化指標」。
* 句首或句尾用「才能」收束，但前文未交代條件/門檻 → 補上「若要…需先…」或「因此…」。
* 出現「收斂」「壓成一句話」→ 改為「可概括/可整理」。
* 出現「跑出」「塞回」「中間走」「輸出前跑」「最後一定要」→ 改為可稽核的流程動詞（建立、納入、檢核、退回補正、回報與版本控管）。
* 同一句出現 3 個以上括號或「＋」符號 → 多半需要拆句或改成冒號＋分號。


8. 修辭邊界（戰爭隱喻、宏大敘事、過量引號括號）

8.1 軍事/戰爭隱喻（S3：對外文章高度避免）

* ❌ 戰略高地、鉗形攻勢、降維打擊、彎道超車、攻堅、主戰場、保衛戰、全面開戰、碾壓
* ✅ 關鍵位置/關鍵優勢點／雙管齊下/兩端同時施壓／後發先至/把握轉型窗口／集中資源突破…
  管理語境長期挪用軍事隱喻，容易把分析寫成對抗式口號；用中性機制語言通常更精準。([MURAL](https://mural.maynoothuniversity.ie/id/eprint/20178/))

8.2 宏大敘事（S2–S3：避免用它當論證）

* ❌ 大勢所趨、歷史必然、百年未有之大變局、頂層設計、星辰大海、大棋局
* ✅ 改成條件句＋時間範圍＋對象：
  「若利率維持高檔且融資成本上升，投資意願可能在未來 2–3 季受到壓抑；但仍需看產業訂單能見度與政策工具介入程度。」

8.3 引號與括號（S1–S2：節制）

* 引號只用於：直接引語、特別指稱；且使用教育部建議的「」『』。([語文成果入口網](https://language.moe.gov.tw/001/upload/files/site_content/m0001/hau/Revised_Handbook_of_Punctuation.pdf))
* 括號只做必要夾注；避免一句三層括號
* 英文術語第一次：中文（English）一次即可；後續只用中文（除非辨識必要）

9. 段落模板庫（按 doc\_type 套用）

9.1 商管專欄（一般/主管）

1. 一句話結論（不喊口號）
2. 背景：為何此案例/此議題重要（範圍：產業/時間/對象）
3. 觀察：具體變化（指標或行為）
4. 機制：2–4 個原因（分點）
5. 影響：對企業/供應鏈/就業/投資的傳導
6. 限制：哪些不確定、替代解釋
7. 指標：接下來看什麼（數據/事件）

9.2 財經分析（投資/研究）

* 問題定義 → 假設/前提 → 數據與來源（無則明說） → 機制 → 情境推演（上/中/下） → 風險提示 → 觀察指標

9.3 研究報告（學術讀者）

* 摘要（研究問題＋主要發現） → 文獻/概念框架（精簡） → 資料與方法 → 結果 → 討論（機制/含意） → 限制 → 建議/後續研究

9.4 政策簡報稿（公部門/董事會）

* 背景與目的 → 現況摘要（3–5 點） → 影響評估（短/中/長） → 選項與配套 → 建議方案 → 需決策事項清單

9.5 新聞整理（倒金字塔）

* 第一段：最重要訊息（誰/做什麼/影響）
* 第二段：補脈絡（背景/原因）
* 第三段：補細節（數據/引述/時間點）
* 第四段：延伸（後續觀察/可能發展）
  倒金字塔的核心是“重要性排序”，教育部教材亦採此方式訓練新聞稿寫作。([教育局網站](https://ws.moe.edu.tw/001/Upload/1/relfile/7848/41485/26b9c80a-69c9-49b8-b713-ab7971924a22.pdf))

10. 不要誤改清單（避免過度矯正）

以下詞在台灣其實常用，或屬中性通用詞；除非連發造成官腔，否則不必硬換：

* 基本面、現金流、供應鏈、外溢效應、結構性因素、風險評估、產能、需求、通縮、指標（但避免官腔式連發）

另外：

* 「落地」若表示“落到地面/落地窗/出生”，保留；若表示“政策實施”，才改為上路/推動/實施。

G3 是否仍有「在長/在降/在卷」半截句？

13. 測試用例（示例，不新增事實）

原句（陸式口播＋二分斷言）
「你聽到他們開始用票據，你就應該明白：不是不想付，是沒有現金付。按常識講，這不是週期，是系統的現金循環在出問題。」

標準版（台灣商管語氣）
「若付款方式由現金轉為票據或延長帳期，通常代表現金部位較吃緊，或付款節奏改變。這種變化未必只是一時景氣循環，也可能反映資金週轉環境轉緊；但仍需確認是否集中於特定地區、制度安排或專案類型。」

原句（互聯網黑話＋宏大敘事）
「這波內卷會把中小企業直接打穿，大家必須搶佔戰略高地，做大做強，才能彎道超車。」

快修版
「這波競爭加劇可能壓縮中小企業的獲利空間。企業需要重新盤點核心優勢與資源配置，選擇更有利的市場定位與成長策略，才能在轉型窗口中取得相對優勢。」
